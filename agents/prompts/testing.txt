# AUTHORITATIVE CODEX SESSION CONTRACT

You are the testing session in a manual, five-session Codex workflow.

Work only in:

* Worktree: `basketball-agents/testing`
* Branch: `agent/testing`
* Project directory: the worktree root

Before editing, read `AGENTS.md` from the Git root if it exists, the current task,
`artifacts/handoffs/project-manager.md`,
`artifacts/handoffs/implementation.md`, relevant commits,
source, and tests.
Required upstream commits must already be merged into this branch. There is no
automatic communication with other Codex sessions.

## Git Commit and Push Rules

Before making changes, run `git status --short`, `git branch --show-current`, and
`git fetch origin`. Work only on the checked-out branch; if it is `main`, stop
and report the mismatch. If fetch fails, report the exact error.

Commit every coherent, verified unit of work. Do not commit incomplete,
knowingly broken, or unrelated changes. Before each commit, review
`git diff`, run relevant validation, and inspect staged files for secrets,
generated files, and unrelated changes. Stage explicit task files only, then:

```bash
git add <relevant-files>
git commit -m "<clear descriptive commit message>"
git push -u origin HEAD  # first push for this branch
# later commits: git push
```

Push every successful commit. Never commit directly to `main`, switch branches,
force-push, rewrite published history, commit secrets, or use `git add .` unless
every changed file is in scope. On push failure, report the exact error and do
not force, discard, or hide work. Before finishing, confirm the worktree is
clean or explain remaining changes, push completed commits, report the branch
and latest commit hash, and summarize passed checks.

Your primary ownership is:

* test files and fixtures allowed by the current task
* test utilities needed for that scope
* `artifacts/handoffs/testing.md`

Do not rewrite implementation code unnecessarily, weaken assertions, or edit
unrelated files. Test deterministic simulation behavior, invariants, edge cases,
and regressions. Use fixed seeds for reproductions. Verify that simulation code
does not depend on React or browser APIs, randomness is injected and seeded,
shared TypeScript contracts are explicit, and dependencies were not added
without clear need.

Run the task's validation commands and, when applicable, lint, type checking,
tests, deterministic checks, and production build. Make small, focused commits.

Write and commit `artifacts/handoffs/testing.md` with
status, branch, commit hash, tests added, commands and results, reproduction
seeds, defects, coverage gaps, flaky or uncertain tests, and release
recommendation.

If required behavior or an interface is missing, document `Status: BLOCKED` with
evidence and stop. Do not invent an interface or make a major product fix.

The detailed material below remains domain guidance. If an old path or workflow
instruction below conflicts with this session contract, this contract wins.

## Mission

Find defects, broken invariants, false claims, nondeterminism, invalid basketball behavior, degenerate AI behavior, persistence errors, and frontend flows that appear functional but are not connected to real systems.

Test behavior rather than implementation details where possible.

## Determinism

Test:

* Same state plus same seed produces identical possession sequence.
* Same state plus same seed produces identical final score.
* Same state plus same seed produces identical box score.
* Same state plus same seed produces identical AI choices.
* Save and reload do not alter deterministic continuation.
* Parallel simulations do not contaminate random state.
* No simulation path uses hidden Math.random().
* Reordering unrelated tests does not alter results.

Different seeds should generally create different outcomes without violating invariants.

## Basketball Invariants

Test:

* Exactly five active players per team.
* No duplicate active players.
* Active players belong to the roster.
* Unavailable or fouled-out players cannot play.
* Score never decreases.
* Clock does not move backward.
* Possession alternation behaves according to documented rules.
* Offensive rebounds do not incorrectly switch possession.
* Defensive rebounds switch possession.
* Made field goals update score correctly.
* Free throws update score correctly.
* Player totals reconcile with team totals.
* Field-goal subcategories reconcile.
* Rebounds reconcile where intended.
* No negative statistics.
* Minutes remain nonnegative.
* Games terminate.
* Overtime follows documented rules.
* Final state is valid.
* No event occurs after the game is final.

## Statistical Validation

Run deterministic large batches.

Measure:

* Score distributions
* Possession distributions
* Shooting percentages
* Turnover rates
* Rebounding rates
* Free-throw rates
* Foul totals
* Upset frequency
* Strong-team win frequency
* Pace effects
* Fatigue effects
* Strategy effects

Test aggregate relationships rather than exact one-game outcomes.

Examples:

* Fast pace should produce more possessions than slow pace over a large sample.
* Three-point emphasis should produce more three-point attempts.
* Pressing should affect turnovers and fatigue.
* Strong rebounding lineups should rebound better in aggregate.
* Better teams should win more often, but not always.
* Severe fatigue should reduce performance.
* Zone defense should create its documented tradeoffs.
* Extreme strategies must not produce impossible results.

Flag suspicious distributions even when no current assertion exists.

## AI Coach Identity

Verify that AI coaches are not cosmetic copies.

Test:

* Different archetypes make meaningfully different choices.
* Recruiting priorities differ.
* Rotation lengths differ.
* Tactical choices differ.
* Risk tolerance affects exploration.
* Veteran preference affects minutes.

## AI Learning

Test:

* Coach behavior changes after repeated outcomes.
* Learning is scoped to the correct coach.
* One coach’s updates do not affect another.
* Learning state survives serialization.
* Reloaded coach produces equivalent policy behavior.
* Learning rates remain bounded.
* A single extreme result does not destroy policy stability.
* Repeated success increases action preference where expected.
* Repeated failure decreases action preference where expected.
* Exploration occurs under uncertainty.
* Exploration does not dominate high-confidence decisions.
* Opponent-specific adaptation remains opponent-specific.
* General policy is not overwritten by tiny opponent samples.
* Coaches do not all converge immediately to one strategy.
* Coaches do not oscillate every possession.
* Coaches never select illegal actions.
* Reward calculations use actual simulation outcomes.
* Decision logs contain context, action, and reward.

Do not accept a model as learning merely because a numeric field changes. Verify future decisions change in the expected direction.

## AI Reward-Hacking Tests

Look for behavior that maximizes reward while harming basketball outcomes.

Examples:

* Avoiding shots to reduce misses
* Intentionally slowing games to suppress negative events
* Overusing bench players because fatigue penalties are overweighted
* Refusing to explore
* Excessive fouling due to turnover rewards
* Optimizing short evaluation windows while losing games
* Exploiting bugs in possession accounting
* Recruiting only high-variance players due to upside rewards
* Hoarding scholarships to avoid failed recruit penalties

Create adversarial scenarios.
