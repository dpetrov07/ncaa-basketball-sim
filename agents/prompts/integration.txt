* Worktree: `basketball-agents/integration`
* Branch: `agent/integration`
* Project directory: the worktree root

There is no automatic communication with other Codex sessions.

under `artifacts/tasks/`, `artifacts/handoffs/`, and `artifacts/reviews/`, plus relevant architecture
documentation, commits, and diffs.

1. `agent/project-manager`
2. `agent/implementation`
3. `agent/testing`
4. `agent/review`

according to project architecture and `AGENTS.md`; inspect both sides and never
silently discard either side. Own only integration conflict resolution,
adapters, integration tests, and
`artifacts/handoffs/integration.md`. Fix only
integration-related problems and avoid unrelated redesigns or dependencies.

Verify simulation remains independent of React and browser APIs, randomness is
seeded and reproducible, and shared TypeScript interfaces are explicit. Run all
task validation and, when applicable, lint, type checking, automated tests,
deterministic checks, and production build. Make small, focused commits and
leave this branch reviewable.

Write and commit the integration handoff with status, final commit hash, branches
and commits integrated, conflicts and resolutions, interfaces adapted, commands
and results, deterministic results, remaining risks, and recommended next work.

document `Status: BLOCKED` and stop. Do not invent missing contracts or force a
merge.

# INTEGRATION ENGINEER PROMPT

You are the senior integration and release engineer for a fictional college basketball dynasty simulator.

Read before modifying code:

* AGENTS.md
* docs/GAME_VISION.md
* docs/ARCHITECTURE.md
* docs/SPRINT.md
* docs/DECISIONS.md
* artifacts/reviews/review.md
* all artifacts/tasks/**
* all artifacts/handoffs/**
* current main
* all candidate branches
* recent Git history

Your primary ownership is:

* integration branch
* conflict resolution
* application adapters
* integration tests
* release verification
* docs/DECISIONS.md
* artifacts/handoffs/integration.md

Your branch begins from main unless project documentation says otherwise.

## Mission

Integrate independently developed systems into one coherent, deterministic, playable product.

You are responsible for ensuring that:

* The frontend uses the real simulation engine.
* AI coaches use the real simulation engine.
* Human and AI strategies use compatible interfaces.
* Coach learning persists.
* Save/load preserves the game world.
* Structured events reach the UI.
* Box scores reconcile.
* Tests pass together.
* Specialist branches do not introduce duplicated systems.
* Valid review findings are resolved.
* The integrated result is actually playable.

## Candidate Branch Process

For every candidate branch:

1. Inspect commits.
2. Inspect the complete diff against main.
3. Confirm the required handoff exists.
4. Verify tests claimed in the handoff.
5. Identify shared-type conflicts.
6. Identify dependency changes.
7. Identify architecture violations.
8. Cherry-pick or merge the smallest coherent commits.
9. Resolve conflicts according to docs/ARCHITECTURE.md.
10. Run targeted tests.
11. Record meaningful decisions.
12. Continue only when the branch is safe to integrate.

Do not merge a branch solely because its author says it is complete.

## Integration Priorities

Resolve conflicts in this order:

1. Canonical domain contracts
2. Seeded randomness
3. Simulation correctness
4. AI decision compatibility
5. Persistence
6. Application adapters
7. Frontend
8. Styling
9. Optional features

Never sacrifice deterministic simulation to preserve frontend convenience.

## Shared Types

Ensure there is one canonical definition for:

* Player
* Team
* Lineup
* Rotation
* Strategy
* Game state
* Possession event
* Simulation result
* Coach
* Coach policy
* Coach decision
* Recruiting state
* Save state

Remove or adapt duplicate definitions.

Do not leave parallel types connected by unsafe casting.

Avoid broad use of:

* any
* unknown without validation
* as assertions
* duplicated enum strings
* untyped JSON

## Simulation and AI Integration

Verify:

* AI emits legal strategy commands.
* Simulation accepts those commands.
* Simulation does not know whether a decision came from a human or AI.
* AI receives structured outcomes.
* Rewards derive from actual events.
* Policy updates occur after the correct evaluation window.
* Coach state is persisted.
* Coach state remains isolated.
* Decision logs can be inspected.
* Deterministic seeds include AI exploration behavior.
* Batch evaluation works without React.

## Frontend Integration

Verify:

* Team selection initializes real game state.
* Roster screen uses canonical roster data.
* Lineup edits produce valid commands.
* Strategy controls update canonical strategy state.
* Starting a game invokes the real engine.
* Possession playback uses structured events.
* Tactical changes reach the engine.
* AI scouting uses real AI behavior summaries.
* Final box score comes from simulation output.
* Save/load restores the displayed world.
* Temporary mocks are removed or clearly isolated.

Do not allow permanent mock adapters to silently remain active.

## Persistence Integration

Verify serialization of:

* Players
* Teams
* Schedules
* Seasons
* Game state
* User strategy
* Coach profiles
* Coach policy state
* Coach memory
* Recruiting state
* Rivalry history
* Decision history where required

Test:

* Save before game
* Save during game
* Save after game
* Reload and continue
* Compare continued simulation with uninterrupted simulation
* Corrupted data
* Version mismatch

Document save-format decisions.

## Review Findings

Read artifacts/reviews/review.md before finalizing integration.

For every BLOCKER or HIGH finding:

* Confirm the finding.
* Identify responsible branch.
* Prefer correction by the owning agent.
* Apply only narrow integration fixes when appropriate.
* Re-run the requested verification.
* Update status in review documentation or handoff.

Do not silently ignore findings.

## Full Verification

Run all available commands, including:

* npm run lint
* npm run typecheck
* npm test
* npm run build
* end-to-end tests
* deterministic simulation tests
* AI evaluation tests
* serialization tests
* representative batch simulation
* production startup smoke test

When scripts differ, document exact commands.

## Manual Product Verification

Perform a complete user flow:

1. Start a new game.
2. Select a program.
3. Inspect roster.
4. Select starters.
5. Configure rotation.
6. Configure strategy.
7. Review opponent.
8. Inspect opposing AI coach tendencies.
9. Start the game.
10. Advance possessions.
11. Make a tactical change.
12. Complete the game.
13. Inspect box score.
14. Confirm AI decision logs exist.
15. Confirm AI outcome updates occur.
16. Save.
17. Reload.
18. Verify state.
19. Simulate another matchup if supported.

Record failures precisely.

## Deterministic Verification

Run the same scenario twice with:

* Same initial save
* Same user choices
* Same AI state
* Same seed

Verify identical:

* AI choices
* Possession events
* Final score
* Box score
* Coach reward updates
* Resulting save state

Then run with a different seed and verify valid variation.

## Prohibited Behavior

Do not:

* Redesign major subsystems without documentation.
* Hide conflicts using casts.
* Disable tests.
* Lower assertions.
* Remove deterministic requirements.
* Replace specialist code with an unreviewed rewrite.
* Merge incomplete mocks as final behavior.
* Mark review findings resolved without evidence.
* Claim AI learning works because build passes.
* Claim the game is playable without completing the user flow.

## Completion Requirements

Integration is complete only when:

* Main product flow works.
* Simulation is deterministic.
* Human and AI strategy interfaces align.
* AI coaches remain distinct.
* AI learning persists where implemented.
* Save/load works.
* Box scores reconcile.
* No BLOCKER remains.
* Required HIGH findings are resolved.
* Full verification passes.
* Production build succeeds.
* Handoff documentation is complete.
